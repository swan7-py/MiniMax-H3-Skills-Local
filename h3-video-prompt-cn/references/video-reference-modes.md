# 视频参考（`<Video N>`）三玩法 · 实测判据

> 来源：H3 视频参考三玩法对照测试 batch_01（2026-10-22）—— 参考图（四视图角色卡）+ 参考视频（9.4s 滑板黑翼少女，720×1280 / 24fps / 无音轨），跑通 11 组提示词，成片 7 条。
>
> **官方契约优先**：三玩法的定义与组合写法、`fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference` 四种保留标记的语义，**以 `references/ref-en.txt` 为准**（任务类型表、retention 标记表、以及「只提供运镜 / 剪辑 / 节奏 → 属 `reference generation`」那条判据）。本文件**不重复定义**，只补官方没写的**实测判据与写法模板**。

## 一、三玩法怎么选（实操版）

| 你要做的事 | summary 前缀 | `<Video 1>` 的 retention 标记 | 本次实证 |
|---|---|---|---|
| 直接改源片（换人 / 换装 / 换风格 / 换渲染） | `[video editing]` | `partially_preserved`（写明被替换的那一项） | 1-A / 1-B 成立；1-C / 1-C+ 失败 |
| 从源片末帧往后接 | `[video continuation]` | `fully_preserved`（作为续写起点） | 2-A / 2-B 成立；2-C 失败 |
| 只借机位 / 剪辑 / 节奏 | `[reference generation]` | `weak_reference` | 3-A 部分有效 |
| 把源片的动作迁移到新主体 | `[reference generation]` | **`attribute_transfer`** | 3-B 定稿成立 |

三条边界：

1. **`<Video N>` 只管整片关系**；从视频里复用的可见内容一律走 `<Subject N>`。
2. `[video editing]` 的 `summary` 在前缀后必须写 **`The target video is an edited version of <Video 1>.`**
3. **⚠️「风格转换」一词两义**：给源片换皮＝ `video editing`；拿源片风格造新片＝ `reference generation`。开写前先问清是哪种——判错就白跑。

## 二、video editing 天生保守（最省力解＝照抄源片）

**现象**：1-C 想把源片转二维赛璐璐动画，输出**仍是源片本身**，风格零变化。强化后（1-C+：把"保留"限定到几何与运动、外观明确写"重新绘制"、逐镜逐元素给平涂 / 描边 / 两档明暗规则）**仍然无效**。

**定因**：`video editing` 下模型最省力的解就是复现源片。当提示词里"保留"条目多而强、改动只有一两条抽象指令时，**保留会压倒改动**。

三条改法（按有效性排序）：

1. **把"保留"限定到几何与运动**：人物 / 动作 / 机位 / 剪辑点可以保留，但**外观必须明确写"重新绘制"**，而不能只是"保留"。
2. **逐镜逐元素给新的属性规则**：不要只在开头声明一次；每个镜次对每个元素（头发 / 脸 / 衣 / 配件 / 道具 / 地面 / 天空 / 背景）都给一次新外观规则。
3. **给一个具体的视觉目标**：纯文字改渲染没有落点 → 见 §三。

## 三、风格 / 渲染类改动：必须挂具体视觉目标 + 关键帧参考

**实测结论：纯文字风格转换无效**（1-C / 1-C+ 两轮均失败）。

杠杆排序（强 → 弱）：

1. **关键帧参考（首帧 / 关键帧锚）——本次确认的必要条件**
2. 风格参考图**内联进 `<Subject N>`**（内联，不独立成条）
3. 风格 LoRA
4. 纯文字（最弱，实测无效）

### 给用户的建议

- **风格转换务必加关键帧参考**：否则风格转换会失效。本批 1-C / 1-C+ 均未挂关键帧锚，这是失效的主要原因之一。
- **备选路径（待补对照 · 本批尚未验证）**：改判 `[reference generation]`，源片只当结构参考（`<Video 1>` 标 `weak_reference`），内容按新风格重新生成——代价是不再逐帧对齐源片；同时配**风格参考图内联**或**风格 LoRA**。这条只是建议，尚未有本批成片背书，落地前请补一轮对照。

**合规提醒**：关键帧锚作为 `<Picture N>` 独立成条是**合法**的（属"首帧 / 末帧 / 关键帧锚"用途）；后续段落可继续引用该编号，编号全局不变（SKILL.md 硬规则 ③）。风格参考图若只提供风格，则**内联进 `<Subject N>`**，不独立成条。

## 四、动作迁移（`attribute_transfer`）写法模板

**判据**：**属性转移给另一可辨识主体**＝ `attribute_transfer`；**只留大致气氛 / 结构**＝ `weak_reference`。两者写法完全不同，标记写错就直接变成另一种结果——本次 3-B 定稿（`attribute_transfer`）与 3-B 旧版（`weak_reference`）正是这组对照：旧版只是"同节奏的新动作"，并未逐帧复刻源片运动。

**模板要点**：

1. `<Video 1>` 的定义句必须声明它是**全部运动与机位的唯一来源**，并逐项枚举：
   位置 / 朝向 / 身体轮廓 / 位移轨迹与速度 / 姿态 / 占位体积 / 与道具的接触关系 / 逐镜机位 / 硬切点 / 推进节奏。
2. `<Subject 1>`（新角色）标 **`partially_preserved`**：外观（脸 / 发 / 服装）保留，**运动沿用源片**。
3. `summary` 里点明：她的动作**逐帧沿用 `<Video 1>`**，出现在画面里的每一个动作都是 `<Video 1>` 中已经存在的那些。
4. **每一镜**都重复写一遍"位置 / 朝向 / 身体轮廓 / 位移轨迹与速度 / 姿态 / 占位体积逐帧沿用 `<Video 1>`"。
5. 场景、道具等新元素标 `weak_reference`（只保留存在与占位，细节自由生成）。

**写法示范（节选，仅示范结构）**：

```text
subject_definitions:
<Video 1> 是本片全部运动与机位的唯一来源：她在其中的位置、朝向、身体轮廓、位移轨迹与速度、姿态、占位体积，与 <Subject 3> 之间的踩踏位置和接触关系，以及逐镜机位、硬切点与推进节奏，全部沿用 <Video 1> 对应时刻的可见内容。

retention_analysis:
<Video 1> (运动与机位来源): attribute_transfer - 位置、朝向、身体轮廓、位移轨迹与速度、姿态、占位体积、接触关系、逐镜机位、硬切点与推进节奏整体迁移到成片。
<Subject 1> (appears in [Shot 1], [Shot 2], [Shot 3]): partially_preserved - 脸型、发型与服装完整保留；位置、朝向、身体轮廓、位移轨迹与速度、姿态与占位体积沿用 <Video 1>。

detailed_description:
[Shot 1] <Subject 1> 踩着 <Subject 3> 出现在场地上，她的位置、朝向、身体轮廓、位移轨迹与移动速度、姿态与占位体积逐帧沿用 <Video 1> 中对应时刻的运动。
```

**自检**：含 `attribute_transfer` ＋ "唯一来源" ＋ 每镜"逐帧沿用"；`<Picture` 编号在各段一致、无新起编号。

## 五、video continuation 的边界

- **能成**：接住末帧状态（如凌空姿态）→ 落地 → 加速 → 转弯 → 远去，动作连贯（2-A）；续写过程中再引入由 `<Picture 1>` 定义的新角色、与之同框交错也可行（2-B）。
- **不成**：**机位大角度重构**。让镜头从背后绕半圈到正面（2-C）**无明显效果**，模型倾向沿用源片机位。→ 续写只改动作与内容，**不要指望改机位**。
- **⚠️ 末帧续接要加关键帧参考**：否则生成段开头会**多出约 1 秒的前置片段**（模型自己补一段起手），衔接被推后。给末帧挂关键帧锚即可压掉这段。
  - 合规：末帧锚同样以 `<Picture N>` 独立成条，在 `subject_definitions` / `retention_analysis` 声明；后续段落如需指它，沿用同一编号。

## 六、换人一致性（character swap）—— 含身份 LoRA 选型

> 本节的 LoRA 属**身份 / 一致性域**，与 `references/camera-and-lora.md` §五 的**运镜 LoRA**台账不是同一维度，选型时分开查。

### 6.1 两条路线实测（同一源片 + 同一角色卡对照）

| LoRA | 类型 / 接线 | 一致性实测 | 结论 |
|---|---|---|---|
| **Alissonerdx character-swap v1.1** | guide-latent 条件；走独立工作流，源视频经 `MiniMaxH3AddGuide(frame_idx=0)` 接入 | **最好**——脸型 / 发色 / 发型 / 服装跨镜稳定 | **推荐** |
| akatz-ai v1.5 | 纯适配器，叠在 Ref2VA 上，端口不变 | 可用，但**源片强特征会回流** | 需更强的提示词约束 |

### 6.2 源片强特征回流 —— 换人的头号失败点

**实证**：源片是披散长发，v1.5 出片变成"披头散发 + 单马尾"混合态。

四条硬性写法：

1. 发型写成**几何可执行句**：`头顶与两侧头发向后收拢、在左后侧扎成一束低马尾，马尾发束垂在左肩前、发尾带自然大波浪` —— **不要**只写"马尾"两个词。
2. **逐镜再点名一次**发型与发饰。
3. **禁写会默许沿用源片的词**：源片是长发时绝不能写"长发""飘逸长发"；写"低马尾"，并把收拢方式写死。
4. 在 `subject_definitions` 里加一句规范句堵住源片外观回流，例如 `她的头发造型来自 <Picture 1>`（`<Picture N>` 出现在 `subject_definitions` 是合规的）。

**写完后自检**：发型句是否几何可执行 ／ 是否每镜点名 ／ 是否残留源片外观词 ／ `<Picture` 编号是否全局一致。
