# 动作迁移类（Ref2VA 六段）

> **先判通道，再定写法。** 本文件覆盖两条路线，写法核心是**相反**的：
> - **路线 A｜原生 `ref_videos` 通道**（不挂任务 LoRA，或挂 TARA）→ **零动作白描 + 七维归属**
> - **路线 B｜MT LoRA + Guide Latents**（`minimax_h3_motion_transfer_v1.0_ref2va` + `MiniMaxH3AddGuide`）→ **按顺序把动作写出来**
>
> 判错路线的后果：在 B 里写零白描 = 丢掉官方要求的动作顺序；在 A 里写动作顺序 = 文字压过视频参考，模型照文字演一遍。

## 〇、怎么判通道

| 看什么 | 走路线 A | 走路线 B |
|---|---|---|
| 任务 LoRA | 无 / `..._tara_v1.0_ref2va` | `..._motion_transfer_v1.0_ref2va`（或 `..._ffp_v1.0` → 见注） |
| 接线 | 源片 → `136.ref_videos.ref_video_0` | 源片 → `AddGuide.image`，**`ref_videos` 断开** |
| 有没有 `MiniMaxH3AddGuide` | 无 | **有**（latent 取自 `136[1]`） |
| 触发词 | 无 | **首行 `motion_transfer:`** |

**官方原话**：`Guide Latents 路线不用 ref_video_1 通道`；`Disabling TARA alone does not turn native reference conditioning into Guide Latents`。两条路线**不能混用**。

> `..._ffp_v1.0_ref2va` 属第三条：**首帧传播 / 编辑传播**，触发词是 **`vfx_edit:`**（写 `motion_transfer:` 完全不触发），只改第一帧、改动自己蔓延全片，**不演动作**。它不在官方四个 ComfyUI 工作流里。

# 路线 A｜原生 `ref_videos` 通道

> 来源：2026-10-14 赛博朋克滑板动作迁移实测 —— 同参考视频、同 seed、同 9:16、同底座的前提下，
> 5 版提示词 × 2 条管线（SelfLift dasiwa / FreeVideo VDN），用逐帧 Farnebäck 光流做定量判据

## A1. 与「替换 / 编辑类」的分野

| | 本类（动作迁移） | 替换 / 编辑类（见 `editing-and-replacement.md`） |
|---|---|---|
| 源视频提供什么 | **运动、机位、硬切与节奏** | 被编辑的画面本身 |
| 成片画面 | 新片：角色 / 场景是自建的 | 还是那条源视频，只改其中一块区域 |
| `<Video N>` 的 retention | `attribute_transfer` | `partially_preserved` |
| 任务类型 | `[reference generation]` | `[video editing + reference generation]` |

**判据一句话**：成片出来后，源视频的画面内容还在不在？不在 → 本类。

## A2. 症状 → 先排技术故障再改提示词

**症状**：成片动作与参考视频差异极大，**反而与提示词文字一致**。

动手改提示词之前，先排除两个技术原因：

1. **接线**：`119.ref_videos.ref_video_0 → ["<VHS_LoadVideoPath 节点 id>", 0]`，且 `force_rate` = 参考视频帧率、`frame_load_cap` = 目标帧数。
2. **真的被吃进去了**：看 prompt 里有没有 `ref_tokens`（实测 **59968 / 64368** 有值即已编码进上下文）。

**接线没问题 ⇒ 一定是提示词问题。**判据：两条完全不同的底座跑出**几乎相同**的运行数据 ⇒ 不是底座 / 管线变量，只可能是提示词。

## A3. 根因：动作被写成了"可表演的台词"

曾翻车的写法（`detailed_description` 逐镜白描动作）：

> ✗ 约在第 3 秒，她**前脚压住板尾猛然起跳**，**板体离地翻起**、她整个人**腾空**、**双臂向两侧展开**，约半秒后**连人带板落回地面**
> ✗ 她**脚尖拨板使板体沿长轴翻转一整周**
> ✗ 镜头保持中景，**随她靠近缓缓推近**

这是**在给模型写剧本**——文字信号强过视频参考，模型就照文字演一遍。

修正写法：

> ✓ 她的**位置、朝向、身体轮廓、位移轨迹与移动速度、姿态与占位体积**逐帧沿用 `<Video 1>` 中对应时刻的运动
> ✓ 她与 `<Subject 3>` 之间的**踩踏位置、接触点与贴合关系**同样沿用 `<Video 1>`
> ✓ 出现在画面里的每一个动作，都是 `<Video 1>` 中已经存在的那些

## A4. 写法规程（六条）

1. **零动作白描** —— 不写任何可独立表演的动作词。本项目实跑收集的词表（交付前脚本化拦截）：
   `压住板尾 / 起跳 / 腾空 / 翻起 / 板体离地 / 双臂向两侧展开 / 翻转一整周 / 蹲伏 / 快速横穿 / 匀速滑入 / 重心 / 顺式 / 打板`
   判据：这段话能不能让人**不看参考视频就演出来**？能 → 是白描，删。
2. **运动归属七维逐镜声明** —— 位置 / 朝向 / 身体轮廓 / 位移轨迹与速度 / 姿态 / 占位体积 / 接触关系（＋逐镜机位、硬切点、节奏），统一措辞「**沿用 `<Video N>` 对应时刻的运动**」。**每个空间段都要挂一句**。
3. **零机位白描** —— 机位与镜头运动同样归 `<Video N>`。
4. **`<Video N>` 定义升格为"全片运动与机位的唯一来源"**，定义里把七维逐项列名。
5. **收口句必写**（`{{NO_ADDED_EVENT}}` 的正向写法）：「出现在画面里的每一个动作，都是 `<Video N>` 中已经存在的那些。」——放 `summary` + 末镜各一处。
6. **保留 `At MM:SS.mmm` 硬切时刻**；场景与道具仍可自建，身份内联 `<Subject 1>`。

> `overall_soundscape` 里的「起跳与落板闷响」这类**声音描述保留**——声音本来就该具体，且它不是视觉动作白描。视觉段（切到 `overall_soundscape:` 之前）必须零动作白描。

## A5. 骨架

```
subject_definitions:

<Subject 2> 是本片自建的{场景}：{约 50 字定性外观描写}。

detailed_description:

[Shot 2] At 00:05.167, 画面硬切，机位与视角沿用 <Video 1> 在这一时刻的运动。{镜头内的她}沿用 <Video 1> 对应时刻的运动。
出现在画面里的每一个动作，都是 <Video 1> 中已经存在的那些。

overall_soundscape:
{环境声 + 物理动作声}

non_diegetic_music:
{画外配乐}
```

## A6. ⭐ 字数配额与精简边界

同一 `<Video N>` 体系下，**提示词越短，三项运动判据越好，且单调**：

| 版本 | 一采 / 二采 | 提示词字数 | 运动能量 | 与源片时序 r | 光流方向一致度 | 峰值帧（源片 **149**） |
|---|---|---|---|---|---|---|
| **源片** | — | — | **1.935** | — | — | 149 |
| v1 动作白描版 FreeVideo(VDN) | 768×1344（1.03MP 单采） | ≈2600，含动作白描 | 0.966 | −0.182 | 0.096 | 33 |
| v1 动作白描版 SelfLift(dasiwa) | 0.9 / 1.5 | 同上 | 0.963 | −0.039 | −0.056 | 112 |
| v2 改归属句，未精简 | 0.4 / 0.9 | 2622 | 0.552 | −0.015 | 0.132 | 151 |
| v3a（只提分辨率） | 0.9 / 1.5 | 2622 | 0.726 | 0.143 | 0.169 | 101 |
| **v3b（精简）** | 0.9 / 1.5 | **1701** | **1.524** | **0.437** | **0.302** | 17 |
| v3c（极简） | 0.9 / 1.5 | 1416 | **1.650** | **0.495** | 0.262 | 19 |

**结论**

- **剧情叙述 + 大段环境描写与运动抢配额**（H2）。2622 → 1701 字，能量从 0.726 拉到 1.524（**2.1 倍**），r 从 0.143 拉到 0.437。
- **一采分辨率过低也会抹掉运动结构**（H1，次要但必要）：0.4 → 0.9MP 让 r 首次转正。
- ⛔ **精简的边界＝不能砍掉"题材识别特征"**：v3c 把 `<Subject 2>` 压成一句名字 → 赛博朋克公园**退化成普通公园**。
- **取向：1500–1700 字**。身份段、`<Video 1>` 七维归属、`retention_analysis`、每镜归属句、`At` 硬切、收口句**一律不精简**。

## A7. 残余问题（时间轴被压缩）

达标版的峰值帧落在前 1 秒（17 / 19），而源片在 8.0 秒。逐秒能量曲线显示模型把整段动作**压缩到起手 1 秒内演完**——**不是运动几何错了，是节奏分布错了**。
`At` 硬切时刻只对切点有效、**对段内节拍无约束**。

# 路线 B｜MT LoRA + Guide Latents（官方写法）

> 来源：2026-11-04，官方 `minimax_h3_motion_transfer_workflow_native_nodes_v1.0` 模板 + 本机 13 段连续实测
> （单镜头舞蹈，9:16 / 124 帧 / 768×1376，A45 棚拍版 r 0.893–0.971）

## B1. 为什么这条路线要反着写

`AddGuide` 已经把源片编码成 latent **钉在输出第 0 帧起**——动作与时间轴由 latent 保证，不靠文字。所以：

- 文字**不再需要**压住视频（A 路线零白描就是为这个），可以也应该**把动作顺序写出来**
- 官方模板明确要求按 **先 / 接着 / 然后 / 随后 / 最后** 写动作链
- `<Video N>` 只声明 `attribute_transfer`，**不写七维归属**（那是 A 路线为对抗文字压盖而加的补丁）

## B2. 六段结构（与通用六段的三处差异）

1. **首行必须是 `motion_transfer:`**（触发词，删掉等于没挂 LoRA）
2. **没有 `style` 字段**
3. **`overall_soundscape` 与 `non_diegetic_music` 都写 `N/A`** —— 官方工作流**复制源片音轨**，不生成对白 / 音乐（`Audio copies the source soundtrack`）

```
motion_transfer:
subject_definitions:
<Subject 1> 是 <Picture 1> 中那位{人物}：{外观逐项，见 B4}。她在本片里取代 <Video 1> 中那位表演者。
<Picture 2> 是本段画面的第一帧：{姿态 / 发丝 / 光照}；本段从这一帧开始，人物的姿态、发丝走向与光照状态以这一帧为准。
summary:
[reference generation] <Subject 1> 在{场景}里继续那段{动作}：动作顺序、时间节奏、朝向与机位全部取自 <Video 1>，
身份、发型与整套服装取自 <Picture 1>。
retention_analysis:
<Subject 1>（<Picture 1>）：fully_preserved —— {外观清单}在每一帧都保持参考图的样子，转身、背身、被遮挡与大幅甩发时同样。
<Video 1>：attribute_transfer —— 只跟随身体动作、手势、头部与视线、表情、时间节奏、取景与机位；
画面里只有 <Subject 1> 这一位表演者，源片里那位表演者由她取代。
<Picture 2>（首帧锚）：weak_reference —— 只提供本段起始画面的姿态、发丝与光照状态；构图、机位与后续动作仍沿用 <Video 1>。
detailed_description:
[Shot 1] {环境，见 B5}。她在画面中央，全身入画。她先{第一个动作}；接着{第二个}；然后{第三个}；随后{第四个}；最后{第五个}。
全片一镜到底，机位固定；机位高度、景别与取景沿用 <Video 1>，背身就保持背身。她的运动从第一个画面一直持续到最后一个画面，铺满这 {N} 秒。
overall_soundscape:
N/A
non_diegetic_music:
N/A
```

- **单镜源片只写 `[Shot 1]`**，不切分镜。判据：先测硬切——帧差 > **7×** 均值才是真切点；2–3.7× 是快速运动（舞蹈 / 甩发常见），别误判。
- **多镜源片**才用 `[Shot N]` + `At MM:SS.mmm`（见 `cut-and-timing.md`）。
- 收口句「出现在画面里的每一个动作……」**可选**（A 路线必写，B 路线不必）。

## B3. 动作怎么写（这条是本路线的核心）

1. **逐帧抽格核对真实动作**（每 11–20 帧一格），按 **先 / 接着 / 然后 / 随后 / 最后** 串成 4–6 个节拍
2. **只写看见的**，禁发明。写明朝向、手臂位置、头部与视线、腿脚状态、有无甩发
3. **形态用几何描述**，不用形容词：「双臂举过头顶、两手在头顶相握」优于「优美地伸展」
4. **不写机位运动**——「全片一镜到底，机位固定」+「取景沿用 `<Video 1>`」

## B4. 源片外观件：**完全不提**（比替换式否定更彻底）

官方原话：`naming them makes them come back`。实测 13 段（源片是披散长发 + 粉袜 + 牛仔短裤，参考卡是齐刘海高马尾 + 黑袜 + 工装短裤）**零回流**。

- ✅ 只写参考图里那套：`<Subject 1> 是 <Picture 1> 中那位……`，逐项写参考卡的外观
- ⛔ **不要**写「源片里的 X 不保留，改为 Y」——只要还能被指认，就会被拉回来
- 特例：必须保留但改形态的部件（细长发饰、马尾）才用替换式，并补**几何约束**（见 B6-3）

## B5. 场景重塑：必须**彻底重建**

换场景在 B 路线**可以纯文字完成**，但条件是**把源片原有物件全部换掉**：

| 场景 | 做法 | 结果 |
|---|---|---|
| 白天街边 → 夜景 | 只改亮度光位，车 / 树 / 招牌都留着 | ❌ 失败，等于调色 |
| 白天街边 → 五个不同夜景 | 每镜重写一套环境，源片物件全换 | ✅ 成立 |
| 深色棚拍 → 白天草原 | 木地板 / 黑背景 / 顶灯 → 天空 / 草地 / 远山 | ✅ 成立 |

- 官方更省力的做法：挂独立 `<Picture N>` 当 target environment（`<Picture 3> is the target environment: …`）
- **光照必须写位置**，否则模型会摊成平光。写「光从画框之外的正面偏上方均匀铺下」优于「明亮的日光」
- ⛔ **别写太阳**：写「太阳在画面上方偏左」会被画成一个过曝白盘，七帧全顶着一个

## B6. 三个已知坑

1. **锚帧过曝会把场景打崩**：把上一段末帧提亮 1.38 倍当锚，成片**整段退回源片的深色棚拍**（黑丝绒 / 木地板 / 顶灯全回来）。机制：首帧锚是抵消 `ref_videos` 回流的唯一筹码，推到非自然状态后平衡翻向视频通道。**锚帧校色幅度 ≤1.10，超过就会翻车。**
2. **双通道（接 `ref_videos`）会显著摊薄动作**：同一素材同一提示词，A45（断 ref_videos）r 0.893–0.971；B45（接 ref_videos）r 0.457–0.714、峰值帧 4/5 错位。**提示词救不回来，属工作流选择。**
3. **细长小发饰会走形**：蝴蝶结 / 挂饰在小 latent 下容易糊成悬浮丝带。补几何约束——「两条裤腿分开」「蝴蝶结系在发根、缎带尾端垂到锁骨」「挂饰是一颗粉色绒球」——不要把尺寸留给模型猜。

## B7. 提示词之间的字数参照

- 实测区间 **1100–1550 字**（13 段：1240–1543）
- 固定段（身份 / summary / retention / 环境 / 收口）逐段复用，只换动作序列与 `<Picture 2>` 首帧描述 → 保证跨段一致

# 续接（链式长视频）

> 用于把长镜头切成多段串起来。实测 13 段 / 66.67 秒。

## C1. 切段规则

- 每段 **124 帧**（5.167 s），段间**重叠 1 帧**，步进 = 123 帧
- **重叠必须恒为 1 帧**：重叠多一帧，下一段 guide 起点就比首帧锚晚几帧，接缝会跳
- 总帧数必须是 `124 + 123n`。源片不是这个数就**丢尾**（我们丢过 10 帧 / 0.42 s）——把末段起点往前挪会破坏上面那条

## C2. 续接怎么写

- 第 N 段（N≥2）：把第 N−1 段成片**末帧存成图** → `136.ref_images.ref_image_1` → 提示词里**显式声明**：
  > `<Picture 2>` 是本段画面的第一帧：{姿态 / 发丝 / 光照}；本段从这一帧开始，人物的姿态、发丝走向与光照状态以这一帧为准。
- `retention_analysis` 给它 `weak_reference`
- ⛔ **不要写「承接上一段」「延续上一段」**——每段独立生成，模型不知道有上一段。要用**能独立成立的开场状态**表达
- 判据：把「上一段」三个字删掉，这句话还能独立成立吗？

## C3. 链式曝光漂移（B 路线特有）

- 现象：每段比上一段暗一档，**天空一类的浅色大面积最先暴露**（暗背景素材看不出来）
- 实测：天空 B/G/R 在 s1→s4 掉了 47/42/31，**到 s4–s6 就饱和不再往下掉**，不会一路掉到第 13 段
- ⛔ **不要用提亮锚帧去修**（见 B6-1，会把场景打崩）
- 可接受的做法：接受整体暗一档、后期一次性统一提亮（**一次全局操作，不是逐段校色**）

# 验收：光流四判据 + 链式三判据

脚本：`_frames/diag_motion.py`（Farnebäck，逐帧对齐源片序列）

| 指标 | 含义 | 合格线 |
|---|---|---|
| **运动能量比** | 成片 / 源片 mean 能量 | **0.7 – 1.3×** 源片 |
| **与源片能量时序相关 r** | 运动的"节拍"是否同步 | **> 0.4** |
| **逐帧光流方向一致度** | 每帧运动方向是否同向 | **> 0.15** |
| **峰值帧位置** | 动作最激烈的时刻是否对得上 | 偏差 ≤12 帧 |

⚠️ **峰值帧错位不等于动作错位**：先抽帧核对两处姿态对不对得上。实测有 2/13 段报错位但逐帧姿态一致（能量分布不同所致的假阳性）。

链式追加三项：

| 指标 | 含义 | 合格线 |
|---|---|---|
| **接缝锚点 NCC** | 上一段末帧 vs 下一段首帧 | ≥ **0.9**（实测 0.93–0.99） |
| **人物占幅差** | 相邻两段人物高度占比之差 | ≤ **2%**（防景别跳） |
| **大色块通道极差** | 天空 / 草地等区域在各段间的极差 | ≤ **18**（防链式漂移） |

# 不属于本文件能解决的（别再归因到提示词）

成片**清晰度**（尤其高速运动的小物体）**不受本套写法支配**：

| 因素 | 结论 |
|---|---|
| **σ 低噪区（σ < 0.5）有没有采样步** | **决定性**。低 σ 定边缘与纹理锐度 |
| VAE 精度 fp16 vs int8_convrot | **已证伪**：往返 PSNR 差 0.00 dB；同 latent 换 decoder 差 57.55 dB / 高频 −0.3% |
| 一采分辨率 + latent upscale | 0.4MP 起步时小物体 token 太少，upscaler 只是插值 |
| **二采（latent 放大 + 3 步 σ0.9035/0.6316/0.3158）** | **放大面积 ≤1.2× 时无意义**：acutance 0.98（边缘一样锐）但 2–4px 微纹理 −16~20%、耗时 +64%。官方那串 σ 配的是**面积 3.16×**，要用二采放大面积须 **≥2.3×** |
| turbo / 步进蒸馏 LoRA 被旁路 | 会让 8 NFE 裸 int8 严重欠采样。（属"加速"性质，不是"效果"LoRA——「动作用 `<Video N>` 承载时不加效果 / 运镜 LoRA」**不适用于它**） |
