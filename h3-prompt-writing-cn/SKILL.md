## 镜头句本体 —— 先看独立库（2026-10-09 更新）

> ⭐ **写任何镜头运动的句子时，第一个查 `h3-camera-motion-lib`（H3 运镜提示词库，专家包内的独立 skill）**。
> 它按运镜族给出**可直接粘贴进 `detailed_description` 的中文镜头句**＋实测状态（✅/🟡/❌）＋推荐 LoRA＋坑，
> **不依赖 camera DSL**——DSL 降级为可选校验，两者冲突时以库的「实测」一栏为准。
> 本文只保留**精简核心纪律**（够你在没装那个库时不踩坑），完整版一律以库为准。

**精简核心纪律（六条，2026-10-09 校准）**：

1. **变量纪律**：摇镜不写焦距；推拉必写「焦距全程锁定在同一档位」；变焦用"变焦"表达 + 机位恒定；横移写「镜头朝向全程锁定」；升降写「镜头姿态全程保持水平」；翻滚必写方向。
2. **书写顺序**：画面里**先出现的东西写在最前面**（遮挡 / 揭示先写前景遮挡物；跨越甩镜航拍先写门洞枝叶高空全景；POV 主体不入画、不写景别区间）。
3. **时刻与配速**：用官方语法 `At MM:SS.mmm`，**配速＝`At` 起点–结束点两个时刻**；禁止「在 3 秒时间内…」这类自造时长短语；时刻会漂移约 ±1s，动作先后次序要用文字兜底。
4. **整圈环绕：圈数与时长必须同时给**——圈数靠「转满一整圈 + 末了回到正面」的收束句，配速靠起止时刻。只给圈数→转多圈或中途停；只给时长→不转或转不完。（写"快速"会让速度词压过收尾句，实测冲过正面转第二圈。）
5. **环境写"描述式"不写"清单式"**：逐一点名"柱列 / 地砖 / 宫灯必须可见"会把画面推宽；改成一句"主体所处的环境是什么"即可。**它是止损手段不是锁半身手段**（实测主体放大 2.4–3×，仍 0/3 达腰部以上）；真要锁取景 → 用 I2VA 真实首帧。
6. **`<Picture N>` 只进 `subject_definitions`**：`summary` 与 `detailed_description` 里出现 `<Picture N>` ＝ 把它当锚点帧，构图会被那张图拽住。两段内 `<Picture` 计数须为 **0**。

**LoRA 一句话**：专用 ＞ 不挂 ＞ Jojocodex（仅特定情况）。
⚠️ **Dutch Angle Slider 权重即倾角：1 ≈ 20°，常用 2.0**（旧记"1.0≈1°、要 10–20"是错的）。

## 工作流 (Workflow)

1. 识别输入模式：T2VA、I2VA、FL2VA、L2VA，还是全参考 Ref2VA。
2. 对于基础文本 / 关键帧模式，阅读 `references/base-en.txt` 并遵循其最终提示词结构。
3. 对于全参考模式，阅读 `references/ref-en.txt` 并遵循其六段改写格式。
4. 保留所选指南中的准确字段名、段落顺序、标签与计时标注。

## 基础模式 (Base Modes)

- T2VA：从文本构建完整的视听时间线。
- I2VA：从首帧开始，并由此向前发展。
- FL2VA：描述首帧与末帧之间的连续路径。
- L2VA：推断一个合理的开头，并收束到给定的末帧。

按 `references/base-en.txt` 所示顺序使用 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。

## 全参考模式 (Full-Reference Mode)

Ref2VA 改写依次使用 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。参考标签在各段之间保持一致。

### 三条硬规则（2026-10-09 更新 · 曾三次翻车，务必先读）

**① `summary` 只讲剧情与参考关系。镜头走向只允许一句「层级概括」（如「一条连续长镜」「三镜交换」「约第 5 秒凝滞」）；镜头运动细节——焦距 / 半径 / 高度 / 角度 / 速度 / 景别 / 摇幅 / 推拉变焦——一律只写进 `detailed_description`。**

- ✓（官方示例）`[reference generation + audio reference] 目标视频展示 <Subject 3> 在 <Subject 1> 中吃饼干。<Subject 4> 带着 <Subject 2> 走进来，萨摩耶扑向饼干。这三镜的互动以 <Audio 1> 作为音色参考，并以一段罐头笑声收尾。`
- ✗（把 summary 写成镜头说明）`…机位随即以恒定半径、恒定高度、恒定焦距、恒定速度顺时针绕完全冻结的她转满一整圈…`
- 自检：summary 内出现 DSL 直译的镜头变量 → 删掉、挪进 `detailed_description`。

**② 参考图角色判据（正向）：图片作首帧 / 末帧 / 关键帧 / 构图锚 → 独立成 `<Picture N>`；图片作角色 / 服装 / 环境 / 风格来源 → 内联进对应 `<Subject N>` 的定义里（"…是 `<Picture N>` 中的…"）。**

- 四视图角色卡属后者：写进 `<Subject 1>`，`retention_analysis` 只列 `<Subject 1>` / `<Subject 2>` 这两行。
- ✗（把角色卡独立成条并当成视角）`<Picture 1> ([Shot 1] 环绕的起点与终点视角): fully_preserved - 环绕自该正面视角起、回到该正面视角止。`
  ——独立成条＝把它声明成构图锚；角色卡承载的是角色，镜头起点由 `detailed_description` 的文字交代。
- 详解见 `references/reference-image-roles.md`；镜头层纪律见 `references/camera-and-lora.md` §一。

**③ `<Picture N>` 只出现在 `subject_definitions`（来源声明）与真正的首帧 / 末帧 / 关键帧锚定——`summary` 与 `detailed_description` 里一律不出现 `<Picture N>`，剧情一律用 `<Subject N>` 讲。**

- 成因：`<Picture N>` 一旦出现在 `detailed_description` 里，模型会把它当成**锚点帧 / 构图锚**，构图被拉回那张图的取景；`summary` 里用它讲剧情同理。
- ✗ `<Subject 1>——<Picture 1> 中的少女——立在床边的地板上` ｜ ✗ `<Picture 1> 中少女的面容与整套汉服在这一刻清晰可见` ｜ ✗ summary 写 `人物身份与造型均来自 <Picture 1>`
- ✓ `<Subject 1> 立在床边的地板上`；参考关系只在 `subject_definitions` 与 `retention_analysis` 里说清。
- **机械自检（交付前必做）**：把 `summary` 与 `detailed_description` 两段抠出来数 `<Picture` 出现次数，**应为 0**。

阅读 `references/ref-en.txt` 了解标签规则、保留分析与完整示例。

## 音频时间线对齐（带对白音频的 Ref2VA）

当输入包含对白 / 人声音频（`<Audio N>`）时，**先转写音频，再设定分镜时间戳**——这是 Ref2VA 带音频时最常见的失败点：说话人错位（角色 A 在画面中说话，而音频已切到角色 B）。

- **音频优先（Audio-first）**：运行 Whisper（`faster-whisper`，模型 `small`）获取每条语料的起止时间戳与说话人 ID（可区分时用 S1/S2）。将同一说话人连续的语料合并为"话轮"；话轮之间的间隙即自然的切分点。将每个 `[Shot N] At MM:SS.mmm` 锚定到这些话轮边界——不要凭空猜测。注意：Whisper 可能听错数字 / 人名（如"心之星"→"星之星"）；时间戳可靠，内容请用用户原始文本。
- **粗对齐，不要紧对齐**：分镜切点应大致匹配音频中说话人切换的边界（±0.5–1s 即可），但**不要**逐帧精确绑定。在每句中间的停顿处切、或删掉所有时间戳让模型自由发挥，都会让节奏变差。
- **硬规则——禁止说话人错位**：绝不让"角色 A 在画面中说话的分镜"与"音频中角色 B 实际在说话的片段"重叠。核对每个 `[Shot N]` 的时间区间与在该区间内实际发声的说话人（S1/S2）一致。

## 输出规则 (Output Rules)

- **对白 / 歌词必须使用 `<d>[Language] ... </d>` 标签（铁律）**：将说话人的身份短语、ID、动作与语气放在 `<d>` 之外；`<d>` 内部只放语言标签与逐字的原始口语内容——保留每一个原词与标点，**不要翻译、改写或追加英文翻译**。示例：`<d>[Chinese] 今天的星星，好像比昨天暗了一点点。</d>`、`<d>[English] I get off at the next station.</d>`。脚本块与每个分镜描述中均须遵守。
- **音频复用模式（fully_copy）——绝不再合成**：当 `<Audio N>` 作为最终音轨复用时，该音频是唯一的语音来源——只描述谁说话、何时说话、且口型跟随音频。不要添加语气 / 韵律 / 停顿 / 情绪指令（如"声音渐弱""学者般语调"），这些会触发再合成导致语音糊掉。
- 改写段落用中文书写；对白、歌词与可见场景文字保留原始语言（歌词保留中文原文，外文对白 / 歌词保留其原文）。
- 按构图、主体、环境、动作、镜头、声音，以及参考内容出现的精确时点来描述每个分镜。
- 避免剧情摘要、未解析的参考标签，以及与请求时长不符的计时。

## 分镜 / 批次 / 参考图 约定（Shot · Batch · Reference）

本 skill 被 8 个本地版设计 skill 调用生成视频提示词时，统一遵循以下定义与硬规则（设计 skill 无需各自重定义，直接引用本节即可）。

### 概念
- **分镜（Shot）**：最小叙事 / 视觉单元，等价于本 skill 提示词里的 `[Shot N]`。每个分镜自带时长，由分镜设计任务决定如何切分。
- **批次（Batch）**：一次 H3 生成单元 = 一组符合本 skill 结构（T2VA / I2VA / Ref2VA / FL2VA / L2VA）的提示词，**可包含多个分镜（≥1）**。一个批次即一次在 H3 节点提交生成的单位；**一个批次 = 一个输出文件**。

### 硬规则
1. **批次时长上限由设备决定，且应在分镜设计前确定**：在每个设计 skill 的「简报 / 起始门」先问用户「本次一次生成几秒？」可选 5s / 10s / 15s（或用户指定值），记为**批次时长上限**并贯穿到分镜设计步骤。分镜设计任务据此把分镜设计在批次内，而非事后强切。
2. **分镜时长一般 ≤ 批次时长（设计期遵守，本步不重切）**：分镜是创作单元，由分镜设计任务按叙事 / 视听决定，设计期就已遵守批次时长上限（一般单镜 ≤ 上限）。本步（视频提示词）**只负责打包**：把设计好的分镜按时长累加归入批次（同批次各镜时长之和 ≤ 批次时长上限），**不重新切分已设计的分镜**。仅当某个分镜本身在设计期就 > 批次时长上限（偶发），才在生成层做「机械分段」：将该分镜切成多个生成子段（如 `Shot 3` → `3a` / `3b`），但**不改动分镜的创意内容与音频时序**——该分镜的音频跨子段连续，仅生成层拼接。
3. **参考图只用占位符，禁止写路径 / 目录**：最终提示词中，参考资产一律用 `<Picture N>` / `<Video N>` / `<Audio N>` 占位符指代（定义见 Full-Reference Mode）。**严禁在提示词里写入任何图像 / 视频 / 音频文件的绝对或相对路径、文件夹目录**。占位符 → 实际文件的映射由用户在 H3 节点侧按端口完成。
4. **一个批次一个文件（不合并）**：不要把所有分镜塞进一份文档。每个批次输出为【一份独立文件】（建议命名 `batch_01.md`、`batch_02.md`…），文件内含该批次全部分镜的 H3 提示词 + 端口 / 顺序 / 时长 / 分辨率设置建议。这样便于逐批次修改与重跑。
5. **motion-context 在连续批次的衔接边界问（H3 跨段运动连续机制）**：当一段连续镜头 / 序列跨多个批次生成时（如某分镜因超上限被机械分段为 3a / 3b，或相邻批次要拼成同一连续场景），在**批次与批次的衔接处**先问用户「是否使用 motion-context？」——它用于保持跨段运动 / 音频连续，但带来副作用：① 衔接处中间 **22 帧会被重复**（22 ÷ 24fps ≈ **0.917 秒**）；② 提示词时间标注上，**第一段（首批次）保持不变，第二段及之后的各段需整体后延 0.917 秒**（其 `[Shot N] At MM:SS.mmm` 时间戳在原始衔接点基础上 +0.917s）。若不使用 motion-context，则按标准衔接（无 22 帧重复、时间标注无需后延）。注意：motion-context 是「批次衔接」闸门，不是「切分单镜」闸门——单镜的设计切分不由它触发。

> 调用方（设计 skill）应在「简报 / 起始门」先问批次时长上限并贯穿分镜设计；「视频提示词」步骤落实：把设计好的分镜**按时长累加打包为批次**（同批之和 ≤ 上限，一个批次一份 `batch_XX.md`），**不重切分镜**；仅当分镜本身超上限时在生成层做机械分段（音频跨段连续）；**motion-context 在连续批次的衔接边界问**（启用则第 2 段起 22 帧重复 + 时间标注后延 0.917s、第 1 段不变）；参考图使用 `<Picture N>` 占位符而非文件路径。无论上游分镜怎么设计，本步保证：每个批次 ≤ 批次上限；分镜创意与音频时序不被强切破坏。

## 批次自含 —— 禁止跨批引用（2026-10-01 用户反复纠正 · 铁律）

**H3 每个批次都是独立生成**：模型看不到上一批的成片，也不知道存在"上一段"。任何指向前一批的措辞都是无效文本，且会让本批丢掉关键状态。

**禁止写法**：`承接上一段` / `延续上一段` / `接着上一镜` / `如上` / `同上` / `双翼自上一段展开后持续保持展开`；`overall_soundscape` / `non_diegetic_music` 里同样禁（`承接上一段的音色 / 电子脉冲`）。

**正确做法——把上一批的「结果状态」改写成本批能独立表述的「开场状态」**：

| ❌ 跨批引用 | ✅ 自含写法 |
|---|---|
| 承接上一段的高速飞行，他仍在疾飞 | 他在高空贴着云海高速掠行，长发与长氅被疾风向后扯成直线 |
| 双翼自上一段展开后持续保持展开 | 双翼在他背后展开着，随他的甩臂与抬臂摆动 |
| 承接上一段的疾速电子脉冲推进 | 开场即起的疾速电子脉冲持续推进 |

判据：**把"上一段"删掉后，这句话还能不能独立成立？不能 → 重写成本批自己交代的画面。**

- 例外：`retention_analysis` 里的 `(出现于 [Shot N])` 是本批**内部**镜号索引，不属跨批引用。
- 批次之间的实际衔接属**分镜设计**，写在批次文件的块外说明里，不进提示词块。
- 自查：写完 grep `承接` / `上一段` / `上一镜` / `如上` / `延续`，块内应为 0。
- **反向同样禁（2026-10-01 二次踩坑）**：`下一段` / `下一镜` / `下批` / `作下一段首帧` 也是跨批引用。末帧图只写「视频以 `<Picture N>` 为末帧收束」；它要作下一段首帧这件事写在块外衔接说明里。

## 道具交接 / 朝向 / 破坏形状（2026-10-02 实跑修正）

- **错握**（手握住剑身而非剑柄）：加**镜头跟随句**"镜头随道具后退半步、把整件道具完整收进画面"，并给**部件次序**"自下而上：手 → 短握柄 → 护手 → 剑身 → 剑尖"；道具定义里就写明握持部位。
- **朝向反了**（写"剑尖朝上"仍朝下）：朝向一律用**部件次序 + 最高/最低点**表达（"剑柄最低 → 剑身竖直向上 → 剑尖是最高的一点"），不要只写"朝上/朝下"。
- **破坏形状对不上攻击形状**（X 形剑气却把山劈成两半）：**破坏结果 = 攻击形状的镜像**——斩几道、什么交叉角度，裂口就是几道、什么交叉角度。
- **抽象施法动作建立不了因果**（写"手臂轻轻一送 → 空气被撕开"，裂口根本没出现）：必须给**起势 → 轨迹 → 中间态（关键：先出现一道细光线/细痕）→ 结果（沿中间态张开）** 四步，并在后一镜回指"这道裂口就是方才那道细线张开后的样子"。

## 否定式描述禁用令（H3 没有负面提示词）

**H3 没有负面提示词（negative prompt）字段，也不理解「没有」。写「没有什么」会让那个东西更容易出现——模型抓住名词就画出来。** 以下结论来自一次真实电商服装测试（同 seed、同分镜，只改否定句）：

| 原写法 | 实际结果 | 改法 |
|---|---|---|
| `a plain flat matte-grey metal slider with no ring, no loop and no circular pull` | 领口与下摆凭空长出金属大圆环拉头 | 删掉整句 → `a flat matte-grey metal slider`，圆环消失 |
| `the image is never globally desaturated` / `never reads as grey, sage-green` / `the fabric is never pushed toward grey` | 画面持续往灰绿偏 | 删除，只留正向色名 `bright pale ice-blue`，颜色回归 |
| `no percussion, no dramatic swell`（音乐段） | 配器里仍有打击乐 | 删除 |
| 胸标镜头（Shot 3）里顺带写了门襟拉链 | 模型把注意力分给拉链，生出「手摸门襟 / 拉拉链」的动作 | 删掉拉链那句，Shot 3 变成干净的胸标镜头 |

硬规则：

1. **只写「有什么」，不写「没有什么」—— 被禁的是「裸否定」**（见下面的两级判定）。`subject_definitions`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music` 里**禁止**出现 `no X` / `without X` / `never X` / `X-free` / `no colour cast` / `no percussion` 一类句式。
2. **要把某个元素去掉，就删掉提到它的整句**，而不是补一句否定。拉链本就没有圆环 → 只写 `a flat matte-grey metal slider`，**不要**再补 `with no ring, no loop`。
3. **要表达「空 / 无」的状态，改成正向状态描写**：`no cars on the street` → `an empty street`；`no text on the wall` → `a bare painted wall`。
4. **要纠正颜色 / 风格，只写正向目标值**（`bright pale ice-blue`、`a clean neutral white balance`），不要用「不要偏灰、不要偏绿」纠偏——点名灰绿只会强化灰绿。
5. **一个分镜只描述这一个分镜要展示的那一样东西。** 不要把别的卖点捎带写进来：胸标镜头里顺带提门襟拉链，模型就会把注意力分给拉链，甚至生出「手摸门襟 / 拉拉链」的动作（实测发生过）。
6. 写完必须自查：全局搜 `no ` / `never` / `without` / `-free` 及中文 `不` / `没有` / `无`，命中即按下面**两级判定**复核，**不要一律删**。

### 两级判定：裸否定（禁） vs 替换式否定（安全）— 2026-09-20 实测修订

**「裸否定」= 点名一个不想要的东西，却不给替代物。** 模型抓到名词就画出来 → **禁**。
**「替换式否定」= 「弃用旧属性 + 显式指定新属性」。** 结构固定为：先点名要丢掉的旧属性，**紧接着用「改为 / 换成 / 而是」给出明确新属性**。此时模型收到的是一条**完整的替换指令**，落点是新属性 → **安全，实战有效**。

| 写法 | 判定 | 说明 |
|---|---|---|
| »`<图片 1>`中粉色睡衣**不保留**，角色改为穿着`<Subject 2>`的牛仔外套« | ✅ 安全 | 点名旧属性（睡衣）后**立刻给了新属性**（牛仔外套） |
| »服装与鞋子**不沿用**`<Picture 1>`，改为穿着由`<Picture 2>…`共同定义的汉服造型« | ✅ 安全 | 同上：弃用 + 指定 |
| »`with no ring, no loop`« | ❌ 裸否定 | 只点名 ring/loop，无替代物 → 长出大圆环 |
| »不要偏灰、不要偏绿« | ❌ 裸否定 | 只点名灰/绿 → 强化灰绿 |
| »不要出现中文« | ❌ 裸否定 | 应改成正向状态描写，或直接删掉整句 |

**判据一句话：否定后面有没有紧跟「改为 / 换成 / 而是」？有 → 安全；没有 → 改掉或删掉。**

> 注意区分：**正向形容词不算违规**——`matte`、`flat`、`plain`、`clean`、`quiet`、`bare`、`empty` 这类是正向写法，正常使用；被禁的是「no / never / without + 名词」这种**指名否定**。

## 替换 / 编辑类四条判据（2026-10-25 定稿）

1. **保留但移位 → 独立成 `<Subject>`**：片中把某物「取下 / 移开」、成片里它仍然可见（眼镜拿在手里）→ 必须编号，并写明此刻在哪；主体外观串里不写它，改写「他的脸是裸露的」。否则一脸一副 + 手里一副。
2. **待清除物件 → 不编号，写进 `<Video 1>`**：眼镜、墨镜、耳麦、耳机、耳返、帽子、手持麦、烟、包……凡成片里不该出现的「身外之物」都按这一类处理。写法：`在源片里，X（可多件并列）标记为待重建区域，成片里该位置由 Y 取代`，并把 `<Video 1>` 的 retention 从 `fully_preserved` 降为 `partially_preserved`。理由：`<Subject N>` 只代表「目标视频中实际会用到的内容单元」，且 retention 标记只有四个固定值、**没有「删除」项**（自造 `removed` 属违规）。**清单要列全**（耳返、手表、戒指、烟最易漏），**替代物要写具体**，**围绕该物件的动作要么一并删、要么改成替换**。
3. **待删物件不能进主体指代**：`本片只替换其中的「带着耳麦的歌手」` 等于要求保留耳麦。指代只写保留类特征（位置 / 服装 / 体型）。
4. **删除用动词**：`本段删除 X` + `只剩 Y` 有效；`不保留 / 没有 / 不出现` 无效（`不出现` 还是 L1 硬拦）。写完用 `[^。；]{0,18}(?:不|没)[^。；]{0,18}` 扫一遍，应为空。

**背景零描述**：`场景、灯光、光位、色彩与背景全部严格沿用 <Video 1> 对应时刻`。不写光点 / 星芒 / 灯束 / LED / 光斑 / 观众席 / 场馆类型——写了就会被画出来（实测背景亮度 33.7→61.7、饱和度 0.042→0.132）。

**参数优先于措辞**：段内自编镜头、背景被重画、首帧画出参考图版式，先查 turbo 权重（换人类建议 ≥0.9）；降 turbo 去「油」会牺牲参考贴合度。实测 7 镜 / 5 秒在 turbo 0.9 下可用。

## 提升效果的技巧 (Tips for Better Results)

- 始终让描述总时长匹配请求视频长度（4–15 秒）。
- 保持参考标签一致（如 `<Picture 1>`、`<Video 1>`、`<Audio 1>`）贯穿每段。
- 偏好具体的视觉与音频细节，而非"cinematic"或"beautiful"这类抽象词。
- 使用关键帧（I2VA / FL2VA / L2VA）时，清楚说明首帧和 / 或末帧如何与时间线连接。
